## 二、Coding 专属承重判定（§11.1 应用）

以下错误会改变承重事项，视为承重结论：
- `git push --force`、`git reset --hard`、分支删除；
- 数据库 Migration、Schema 变更、数据删除；
- 生产环境配置变更、部署切换；
- API 契约变更（可能破坏既有调用方）；
- 依赖大版本升级。

## 三、Coding 专属排他表述（§12.1 应用）

高风险表述："**绝对不影响**现有接口"、"**完全兼容**旧版本"、"**全部**测试通过"、"**保证**无副作用"。

→ 使用前必须检查非目标集合：旧接口调用方、边界输入、并发场景、回滚路径。

## 四、停止条件（§15.3 第 4 问）

当 Coding 场景的 SPP 适配被验证有效（§18.3），且通用条款可覆盖时，合并回 references/ 通用层。
当前保留独立文件是因为 Coding 有专属承重判定与专属排他表述。建议 3 个月后复审。

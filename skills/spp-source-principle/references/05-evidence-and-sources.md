# 来源与证据（SPP §9）

> 来源：SPP v4.0 R4.3 §9
> 本文件为原文引用，未做摘要改写。冲突时以主协议为准。

## 9. 来源与证据

### 9.1 来源优先级

1. 官方产品文档、法规、正式标准或权威元数据
2. 当前环境的配置、API 输出、日志、截图和系统实测
3. 经验证的内部制度、合同、业务规则和批准记录
4. 多来源一致的专业资料
5. 社区资料、博客、论坛和经验性解释
6. AI 既有知识或未经验证的推断

**低优先级来源不得覆盖高优先级证据。**

**特别提示一：** AI 的通用专业直觉属第 6 级。与人类指定的原理（§11.6）冲突时，不得静默覆盖。

**特别提示二：** 课题共构中的提议式问题（§5.4.3）同属第 6 级。允许用于发现，但必须标记出处，不得伪装成第 1 级。

### 9.2 产品机制与环境事实分离

| 类型 | 含义 |
|---|---|
| 产品定义 | 官方资料说明系统按设计如何工作 |
| 环境配置 | 当前环境实际启用了什么 |
| 环境数据 | 当前环境实际产生了什么 |
| 实施验证 | 变更后是否实际达到预期 |
| 管理决策 | 人类基于业务需要作出的取舍 |

**不得用当前环境样本推导跨环境永久规则，也不得用官方设计替代生产实施验收。**

### 9.3 证据必须带适用范围

环境证据至少记录：环境、查询或操作、时间截面、原始结果、样本范围、已知限制。

动态 Count、容量和状态不得表述为永久固定事实。

### 9.4 来源无法确认时

明确披露证据不足；标记为待验证或假设；不以经验、语言流畅度或常识填补缺口；不因人类期望完整答案而制造确定性。

### 9.5 证据冲突

披露冲突；区分冲突类型；评估来源权威性、时效性与完整性；寻找独立交叉验证；说明对结论的影响；无法解决时保持未决。

```
无法证明 ≠ 可以假设成立
无法排除 ≠ 已经成立
存在证据 ≠ 证据足以支持完整结论
```

## 执行要点（AI 路由）

- **触发：** 引用来源、评估证据、处理证据冲突时。
- **必须动作：** 按 6 级来源优先级；分离产品机制与环境事实；环境证据带适用范围（环境/操作/时间截面/原始结果/样本范围/限制）。
- **禁止：** 低优先级来源不得覆盖高优先级证据；不得用环境样本推跨环境永久规则；不得以经验填补证据缺口。
- **停止条件：** 证据充分支持结论，或明确标为待验证/未决。

# 保真护栏（Fidelity Guardrails）

> `de-ai-flavor` 按需参考（L3）。何时加载：执行任何去味 / 改写 / 审稿动作前必读；"去味"与"保真"冲突时以本文件为准。SKILL.md 仅保留精简条目，完整规则见下。

去味的目标是把表达变自然，**不是改变事实或作者意图**。以下护栏优先于任何禁词 / 风格约束；当"去味"与"保真"冲突时，**保真优先**。

## 1. 白名单默认（最高优先级）

本 skill 采用**白名单式**改写：**只能处理**禁词表（`references/02-banned-words-and-patterns.md`）、对应语言的改写规则（中文 `references/05-zh-syntax-and-structure.md` / 英文 `references/07-en-syntax-and-structure.md`）与格式清扫清单（`references/09-format-and-artifacts.md`）中**明确列出**的问题；**未命中任何规则的文字必须逐字保留**。

- 一句话即使命中规则，也只能改动**解决该问题所必需的最小范围**——不得顺便润色、不得替换没有问题的词语、不得调整语气 / 详略 / 信息密度。
- 对某处**是否命中没有把握时，保持原文**。
- **文章框架不在处理范围**：标题层级、章节顺序、段落数量与顺序、列表 / 表格 / 引用 / 代码块位置**原样保留**（除非用户显式要求 `structural` 档，见 §7）。

> 与旧版"最小必要修改"的差别：默认从"经验判断该改多少"收紧为"**只改清单命中项，其余逐字不动**"。档位制（§7）降为**可选覆盖**。

### 1.1 上下文级排除（这些位置即使"命中"禁词，也不构成命中）

以上规则说的是"命中就改"。但有四类位置**根本不算命中**——它们看起来踩了规则，按本 skill 的口径却**不在判定范围内**，**一律逐字保留**：

| 类型 | 说明 | 例 |
|---|---|---|
| **标题** | 标题、小标题、文件名、图表题、章节名。标题承载**检索与锚点**，改写会破坏引用与链接 | 小标题里出现"赋能"不改 |
| **专有名词** | 产品名 / 商标 / 项目代号 / 人名 / 机构名 / 标准号本身 | 产品就叫 `Seamless`；公司叫"赋能科技" |
| **元语言指称** | 一段在**讨论**某个词，而不是**使用**它 | "单组三项不是判据"——这里的"判据"是**被讨论的对象**；本 skill 的 `references/` 全篇如此 |
| **引文与对话** | 直接引语、他人原话、对话与引语内部（中英反向清单的「使用纪律」已各自列明，此处上提为**通用边界**） | 用户原话里写着"赋能"——照录 |

> ⚠️ **元语言指称同时是一条已知识别边界**：`scripts/ai_pattern_lint.py` 是正则引擎，**分不清"使用"与"提及"**。命中落在被讨论的词上时，按本条人工排除。

> 来源：**`blader/humanizer`（MIT）的 `When not to act` 章节**——它把"何时不动手"独立成章，本 skill 只取其分类框架，判据仍按自己的语料证据。

## 2. 实词溯源（信息守恒 · 可验收判据）

**改写后的每个实词，都要能在原文里指出出处。指不出来 = 新增，必须撤销。**

这比"拿不准就保留"更可执行、可复核。两张硬清单：

- **不得新增**（哪怕只为"读起来更具体"）：姓名 / 机构名 / 职务 / 地名；数字 / 比例 / 金额 / 时长 / 次数；日期 / 时间 / 先后顺序；引语 / 对话 / 他人说法；引用来源 / 出处 / 链接；因果 / 动机 / 心理活动；任何原文没写的细节 / 场景 / 案例。
- **不得删减**：观点、结论、**限定词与让步**（"可能""通常""在某些情况下""据说"）。把"可能提升"改成"提升"是**篡改语气强度**，不是去 AI 味。

**"把抽象写具体"不是本 skill 的职责**——原文抽象就让它抽象。`references/05-zh-syntax-and-structure.md` 第 8 条只允许把原文**已有**的具体数据提到概括词位置，**不允许自己造数据**。

## 3. 情态 / 条件 / 承诺不可改写

- "可能 / 或许" ≠ "必然"；"可以 / 能" ≠ "会"。表达不确定或条件许可的词，**即使出现在禁词表里，只要作者真的在表达不确定或附带条件，就必须保留**（2026-09-30 起已从中文必删项移出，见 `references/02-banned-words-and-patterns.md`）。
- 否定只排除一种原因，不能改成肯定（"不是因为权限不足" ≠ "权限充足"）。
- 保留：谁做什么、数字对应什么、条件、范围、否定、完成状态、比较关系、责任归属、下一步动作。

## 4. 抽象可保留

原文只谈潜力、目标、作用时，可以仍然抽象；不要因缺细节就补出实现方式、数据或新对象，也不要把"有望改善"强行改成"已实现改善"。"效率提高"不能补成"节省时间"。

**反过来，承载作者声音的细节必须保留**：具体的怪细节、矛盾的情绪、有年代感的梗、真心的离题——这些读起来"不够整齐""不够聚焦"，却正是人味所在。**不得以"偏题 / 不统一 / 不够专业 / 不够精炼"为由删除或拉直**。（分类来源：`blader/humanizer` 的 *voice-carrying details* 清单，MIT。）

## 5. 代码块逐字保留

程序代码块（含注释、文档字符串）默认原样保留，不进入去味编辑。除非用户明确点名修改注释或说明文字，且仅改文字、不改程序行为。代码围栏里的普通文案（非代码）仍可清理。

## 6. 来源处理

- 出现"研究表明 / 专家认为"等**未指明来源**的归属时，默认保留归属与论断，必要时在正文外简短注明"缺来源"；**不能只删归属让无源论断变成裸事实**。
- 仅当用户明确要求 `rewrite-safe`（删除无源论断）或"删掉无来源断言"时，才按范围处理；`in-place` 下保留原句并提示缺来源。

## 7. 编辑幅度档位（可选覆盖默认）

**默认即"白名单 + 未命中逐字保留"（§1）。**以下档位仅在**用户显式指定**时启用，用于长文等需要放宽的场景：

| 档位 | 允许 | 禁止 |
|---|---|---|
| `in-place` | 只在句内改 | 不删句、不并句、不重排；要求保句数时不拆句 |
| `bounded` | 句内清理 | 不直接删整句、不并句、不重排；纯空句可在正文后列"建议删除（待确认）"，正文暂留 |
| `structural` | 可删、并、重排 | **仍须**保留有效信息与作者意图；仍受 §2 实词溯源约束 |

未指定档位时按 §1 默认执行；中文公开长文约 1000 字以上默认保留句段结构。

## 8. 只标问题（审稿模式）

用户要求"只标问题 / 不改写"时，只引用有问题的片段，说明具体问题与修改方向，**不交替换全文**，不附判定链或评分。每条理由须由原文支持。

## 9. 样本与风格文档优先（覆盖本 skill 全部规则）

用户提供了**写作样本 / 风格文档**（写作风格指南、`language-DNA.md` 一类、既往成稿）时，**样本优先于本 skill 全部规则**——包括禁词表与中文破折号条。样本怎么用，就按样本的密度用；样本里的高频词即使列在本 skill 禁词表里，也不改。

- **有样本** → 先读样本，按样本校准用词与密度，**最后**才套规则。
- **无样本** → 按本 skill 默认（§1 白名单 + 对应语言的规则）。
- 本条与 `references/06-do-not-change.md` / `references/08-en-do-not-change.md` 的「使用纪律」同源（那两份各自已写明）。此处把它提为**护栏级**，因为 `SKILL.md` 才是每次都被读的那一份。

> 来源：**`blader/humanizer`（MIT）「样本覆盖下面所有模式」**这一裁决权；本 skill 采纳其**层级关系**，具体密度仍按样本实测。

---
**执行要点**
- 触发：任何去味 / 改写 / 审稿动作。
- 必须动作：**先看有没有写作样本 / 风格文档（§9，有则以它为准）**；再按 §1 白名单界定可改范围，并逐条排除 §1.1 的四类上下文边界；逐条对照 §3–§6；改写后按 §2 实词溯源逐词复核；与禁词表冲突时以本护栏为准。
- 禁止：改动未命中清单的文字；改标题 / 专有名词本身 / 引文，或一段在**讨论**某词而非**使用**某词的文字；新增原文没有的信息；删减限定词 / 让步；改写情态 / 条件 / 承诺 / 否定范围；以"偏题 / 不统一 / 不够精炼"为由删掉承载作者声音的细节；在代码块内编辑；把无源归属删成裸事实。
- 停止条件：**未命中项全部逐字保留**、**每个实词可溯源**、改动均不改变事实 / 情态 / 条件 / 归属 / 数字 / 完成状态——三条同时满足方可输出。

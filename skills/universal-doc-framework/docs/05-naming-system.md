# 05 · 完整命名体系方案（NamingSystem v1.0）

> **文档性质**：体系全景 + 路由。把底稿盘点的**全部命名对象类型**收进一张体系图，每类给出命名式、受控取值与权威指针。
> **权威源**：`aden-naming-standard` v1.4（正文 §1–§10 + 附录 A）与其研究底稿 `docs/11`（§2 资产清单）。本文**不复制条款原文、不复制正则与脚本**；冲突时以上游正文为准，数据对象以《ADEN 分层落盘构建块对照》v1.4 原文为准。
> **与 docs/04 的关系**：`docs/04` 是本文「A1 文档名称」一卷的展开（双形态 + AI 选名表）。本文是全景总纲，04 是其细分子册。
> **双需求**：① ADEN 组织工作 —— 全部沿用集团既有命名式与受控词表；② 本课题六类场景 —— 复用体系、扩展取值、AI 自动选式选值。
> **状态**：v1.0 · Draft · 2026-11-18。

---

## 1. 为什么要成体系

底稿 `docs/11` §2 盘点了 ADEN 的命名资产，**不止文档名称一类**，共 9 类命名对象。此前 `docs/01`–`04` 只覆盖其中「文档名称」一类。本方案补齐全景，并确立一条纪律：

> **一对象一命名式，一取值一注册表。** 不同对象类型进不同命名式，不混用、不并轨（对齐底稿 M1/M2 与裁决 Q2/Q3）。

---

## 2. 命名对象全景（9 类）

| 卷 | 命名对象 | 命名式 | 权威源 | 本方案动作 |
| --- | --- | --- | --- | --- |
| A1 | 文档名称 | `[前缀]-[类型]-[域]-[主体]-[版本][-状态][-语言][.ext]` | 上游 §5.1 | 展开于 `docs/04`，本文 §3 摘要 |
| A2 | ISMS 文件编号 | `<组织>-<域>-<子域>-<类型码><NNN> <中文名>[版本]` | 上游 §6.4 | 引用 + §4.1 详述 |
| A3 | 业务域码 / 子域码 | `NN_名称` | 上游 §6.5 | 引用 + 本地 Draft 补充 |
| A4 | 项目组合（五条线） | 见 §4.3，S1–S5 不并轨 | 上游 §6.2 | 引用 + 决策 |
| A5 | 位置 / 站点码 | 注册表值（IATA + 列名，不并轨） | 上游 §9.1 / 底稿 §2.5 | 纯引用，不复制值 |
| A6 | 对象命名（计算机/账号/组/邮箱） | 见 §4.5 六类 | 上游 §5.8 / 集团标准 | 纯引用 |
| A7 | 内容层标识码 | `<域前缀>-<类型码>-<序号>[<字母>]` | 上游 §7 | 引用 + 类型码登记 |

> **未纳入**：非文档资产（影像/字体/音视频）、明文凭据治理、D365 主数据编号 —— 上游 §1.2 明确不规定，本方案同样不纳入。

## 3. A1 文档名称（摘要，详见 docs/04）

命名式：`[组织前缀]-[文档类型]-[域]-[主体]-[版本][-状态][-语言][.扩展名]`

**受控取值速查**：

| 段 | 取值 | 来源 |
| --- | --- | --- |
| 组织前缀 | `AGI` / `ADEN`（集团）+ `PERS` / `FAM`（本地 Draft） | `docs/04` §3.1 |
| 文档类型 | 13 类 = ADEN 5 类 + 本地 8 类 | `docs/04` §3.2 |
| 域 | 15 个 = 技术域 9 + 课题域码 6 | `docs/04` §3.3 |
| 版本 | `-vX.Y` | 上游 §5.4 |
| 状态 | `-Draft/-Review/-Approved/-Signed/-Retired` | 上游 §5.6 |
| 语言 | `-zh` / `-en` | 上游 §5.7 |

**双形态纪律**：词典形（注册表，带空格下划线）↔ 载体形（文件名，段内大小写分词去空格下划线），一一映射。详见 `docs/04` §1。

## 4. A2–A9 各卷详述

### 4.1 A2 · ISMS 文件编号

```
<组织>-<域>-<子域>-<类型码><NNN> <中文名>[ 版本]
```

| 类型码 | 语义 | 层级 | 流水 |
| --- | --- | --- | --- |
| `MAN` | 管理手册 | 一级 | 独立三位 |
| `SOP` | 程序文件 | 二级 | 独立三位 |
| `INS` | 规范/制度/工作指南 | 三级 | 独立三位 |
| `FOR` | 记录/表单 | 四级 | 独立三位 |

- 完整例：`Aden-SUM-IMP-SOP001 供应商选择管理条例.pdf`
- 唯一性范围 = 每类型码内（上游 §6.1）；类型码固定 4 值，新增走 §9.3。
- **本课题动作**：个人/科研项目**不需要** ISMS 编号；仅 ADEN 正式 ISMS 体系文件使用。**不**把 ISMS 编号塞进普通文档名称式。

### 4.2 A3 · 业务域码 / 子域码

```
主域：NN_名称     子域：NN_名称
```

- 上游既有：主域 `0_Achitect`…`6_General`（`3` 为历史断层保留不占用，§6.5）。
- 唯一性范围 = 域层级内；两位十进制。
- **本地扩展**（`docs/02` Draft）：课题域码 `Software`/`BusinessLogic`/`Reverse`/`AgentCraft`/`Academic`/`Career` —— 语义为**场景分类**，与 ADEN 业务域码**不同空间、不并轨**。文档名称里按 `docs/04` §3.3 用作"域段"，不写成 `NN_` 目录编号。

### 4.3 A4 · 项目组合五条线（不并轨）

| 线 | 形态 | 定位 | 新产物去向 |
| --- | --- | --- | --- |
| S1 | `N_名称` | 早期 capex/opex | 冻结 |
| S2 | `N. <capex\|opex>_名称 - 日期区间` | 项目组合 | 冻结 |
| S3 | 同 S2 | 项目组合续 | **新项目组合入此** |
| S4 | `NNNN. 名称` | 知识域柜 | 按语义扩展 |
| S5 | `NNN_名称` | 文档登记 | **新文档登记入此** |

- 五线物理不合并、跨线重号共存（裁决 Q2）；新产物各线取本线空号。
- **本课题动作**：个人/科研项目**不启用** S1–S5；若需项目流水，用 `docs/04` 的"主体段"自由文本或 A3 课题域码，不占用集团编号线。

### 4.4 A5 · 位置 / 站点码

- 两套注册表**不并轨**（裁决 Q3）：IATA 国家码（上游规范附录 1） vs 列名站点码（`BJG`/`SHA`/`SUZ`/`HQ`…）。
- **纯引用**：本方案不复制码表值，需要时查上游权威位置（底稿 §2.5）。
- **本课题动作**：子类场景（家庭/科研）一般不涉及站点码；ADEN 工作文档如需标注站点，按上游规则引用，**不**自造站点码。

### 4.5 A6 · 对象命名（六类）

| 对象 | 命名式（摘要） |
| --- | --- |
| 计算机名 | `C<IATA2><LT\|DT><Office3>-<部门3><名3字母>` |
| 员工账号 | `Firstname.Lastname<数字>@<域>` |
| 通讯组·团队 | `<总部/区域>-<部门/职能>-<范围>` |
| 通讯组·项目 | `<总部/区域>-<部门/职能>-<项目>` |
| M365 组 | 同通讯组，分隔符改 `.` |
| 共享邮箱 | `<区域/部门>.<function>@<域>` / `<名称>.noreply@<域>` |

- **纯引用**：以上为摘要，完整原文见 `AGI-Group Standard-Front End Naming Convention v0.3`；本方案不改写、不补全。
- **本课题动作**：个人/科研项目不涉及对象命名；ADEN 工作由 IT 治理侧按集团标准执行。

### 4.6 A7 · 内容层标识码

```
<域前缀>-<类型码>-<序号>[<变体字母>]
```

| 组成 | 规则 |
| --- | --- |
| 域前缀 | `INT-`/`EOD-`/`MD-`… 省略=文档级 |
| 类型码 | 2–4 字母，**须登记** |
| 序号 | ≥2 位补零，超 99 自然扩 3 位不重编 |
| 变体字母 | 小写 `a`/`b`/`c` |

- **初始类型码**（上游附录 A.9）：`INT`/`OP`/`EOD`/`MD`/`A`/`FR`/`NFR`/`BASE`。
- 唯一性范围 = （类型 × 域）× 文档（上游 §7.3）。
- **本课题动作**：文档正文内需要引用对象时，用此式编号；类型码不够用时按 §9.3 登记，**不即席造码**（底稿 R-AB-6）。

### 4.7 A8 · 数据对象命名

```
方案 A（采用）：<层容器>.<类型前缀>_<主体>
```

| 层容器（A） | 类型前缀 | 主体结构 |
| --- | --- | --- |
| `ods`/`dwd`/`dim`/`dws`/`ads` | `stg_`/`int_`/`dim_`/`fct_`/`vw_`/无 | 见上游 §5.9.4 |

- 例：`dwd.stg_fo__vendtrans`、`ads.vw_cn_pur_po_ontime_rate`。
- 双下划线 `__` 仅用于 staging/intermediate 机械切分；数据对象名中下划线**必需**，与 §5.2 文件名禁下划线**不冲突**。
- **纯引用**：正则、占位符白名单、保留名清单以《ADEN 分层落盘构建块对照》v1.4 为准，本方案**不复制**。
- **本课题动作**：个人/科研项目一般无数据平台；如涉及，按上游执行。

### 4.8 A9 · 系统异常产物

- 形态：文件名尾部 `-CCNLT<三字母>-<字母串>`。
- 定性：**在线保存失败时系统自动另存的副本**，非人工命名、非敏感度标签（裁决 Q1/Q4）。
- 处置：不纳入命名规则、**不得人工模仿**、列清理候选但须人工比对确认（上游 §1.4）。

## 5. AI 按对象类型选命名式（决策总表）

AI 遇到命名需求，**先判对象类型，再查对应卷**，不混用、不自造（底稿 R-AB-6）：

| 你要命名什么 | 走到哪卷 | 命名式 | 取值从哪查 |
| --- | --- | --- | --- |
| 一份报告/规格/指引/标准文档 | A1 | `[前缀]-[类型]-[域]-[主体]-[版本][-状态][-语言]` | `docs/04` §3 + §4 决策表 |
| ISMS 体系文件 | A2 | `<组织>-<域>-<子域>-<码><NNN> <中文名>` | 上游 §6.4 / ISMS 索引图 |
| 新业务域/子域目录 | A3 | `NN_名称` | 上游 §6.5 + `docs/02` |
| 新项目组合项 / 文档登记号 | A4 | S3 `N. capex/opex_…` / S5 `NNN_名称` | 上游 §6.2–6.3（取本线空号） |
| 文档要标站点 | A5 | 引用站点码 | 上游权威表（不复制） |
| 计算机/账号/组/邮箱 | A6 | 见 §4.5 六类 | 集团 Front End 标准原文 |
| 文档正文内对象（需求/接口/假设） | A7 | `<域前缀>-<码>-<序号>` | 上游附录 A.9 + 登记表 |
| 数据平台 schema/表/视图 | A8 | `<层>.<前缀>_<主体>` | 构建块对照 v1.4（不复制） |
| 遇到 `-CCNLT…` 后缀 | A9 | 无（识别为系统异常） | 清理候选，不得模仿 |

**判不了就问用户**，不默认套 A1 文档名称式。

## 6. 与三层治理 / 双需求接缝

| 维度 | 本方案落点 |
| --- | --- |
| 命名层（上游，不改） | §2 全景 9 卷全部锚定上游权威；不复制条款/正则/码表 |
| 结构层（`docs/01`） | A1 状态后缀随六段骨架推进（`docs/04` §4.4） |
| 识别层（AGENTS.md + skill） | §5 决策总表 —— AI 按对象类型自动路由到命名式 |

| 本课题六场景需求 | A1 扩展取值（8 类 + 6 域码）+ A3 场景分类；其余卷个人/科研项目一般不涉及，已逐卷标注 |

# 00 · 符号与缩写登记表（Glossary）

> **文档定位**：本项目所有**符号化编号**（字母、缩写、序号）的唯一登记处与定义处。
> **为什么要单独开一份**：符号只有两种状态——**已登记**（有定义处、有含义、无冲突）与**未治理**（即席造的、无定义、可能撞车）。
> 允许第二种存在，等于让治理文档自己违反自己主张的治理标准。
> **状态**：v1.0（2026-10-10 建立；因一次审计发现多处字母在同一文档内相互矛盾）。
> **证据分级**：✅已登记 · ⚠️已用但需规范 · 🔴已知冲突待整改 · 🌐外部符号（微软官方，不改造）。
> **标准依据**：本表 §1 的纪律并非自定，而是可援引 **ISO 704:2022 / ISO/IEC 11179-5:2015（命名与标识六原则）/ GB/T 1.1—2020 §3.2.8** —— 详见 `docs/10-abbreviation-and-numbering-standards.md`（全球检索结论：**不存在跨域通用缩写表，只有通用建表方法**）。

---

## 1. 使用纪律（5 条）

1. **先定义，后使用。** 任何字母/缩写首次出现处，必须**同句或同表**给出全称；不得用"见上表 / 见前文"代替。
2. **有注册表。** 全项目符号登记于本文件；新增符号必须**先查表 → 再登记 → 后使用**三步走，不得跳过登记直接使用。
3. **一个轴一套符号，字母不复用。** 同一文档族内，一个字母只属于一个轴；已被占用的字母不得再开新轴。
4. **默认不用缩写。** 能写完整名词就不写字母。字母仅在同时满足「**跨 ≥3 处引用**」且「**已在本表登记**」时才引入。
5. **外部符号不改造。** 微软官方名称（如 SKU 名 `Endpoint P2`、`Anonymous T1`）照抄原样，标注 🌐，**永不与内部符号共用同一字母空间**。

> **判据**：`FR-01` 是好符号，因为 `docs/04` §3 有它的定义表；`D2` 是坏符号，因为它诞生在某段散文里，没有定义处。
> **差别不在格式，在有没有注册表。**

## 4. 整改建议（一次性口径）

**弃用「单字母指代选项」这一做法本身。** 3–4 个选项的一次性枚举，字母**零信息增益**、只带来记忆负担与撞车风险。

| 原写法 | 建议写法 |
|---|---|
| 托管四选 `W / A / P / L` | `WorkBuddy 云` / `租户内 Azure` / `Power Platform` / `本地原型`（全称） |
| 分发三式 `D1 / D2 / D3` | `拉取` / `推送` / `混合`；首次出现括注 `（本文档分发编号 D1–D3）` |
| 载体候选 `T1 / T2 / T3` | `纯推送` / `自建 webapp` / `租户内现成载体`；首次出现括注 `（docs/09 载体编号 T1–T3）` |
| 推送修法 `A / B`（`docs/09` §5） | `自包含（本期采用）` / `放列表 URL（后期）` |

**原则**：**符号只用于「已登记 + 跨多处引用」的对象（需求/条目/基线 id）；枚举选项一律用全称。**

## 5. 维护

- 新增符号 → 先在本表 §2 登记，再使用；未登记即使用的符号视为缺陷，审计时应报出。
- 本表随 `docs/` 演进同步；发现新冲突登记到 §3。
- **分工（2026-10-12 收口）**：本表是**本项目（StreamLens）符号的登记处**——只管"这个符号在这里是什么意思"；**命名与标识的纪律条款**在 `docs/12-aden-naming-and-identifier-standard.md` §5–§8（载体层命名式、编号规则、内容层标识编码、缩写与代号纪律）。二者**不重复定义**：本表 = 登记处，`docs/12` = 条款；条款与登记处冲突时**以登记处为准**。
- **ADEN 载体层命名**（文件名 / 目录名 / 编号 / 文档内标识码）**不在本表范围**，一律以 `docs/12` 为准。
- **字段名与受控取值不在本表范围**（如 `scope`、`review_status`）：它们是数据契约，权威定义处在本项目 `context/`（`03a-contracts.md` §3 / `03-invariants.md` §2）。本表只登记**符号**，不登记**字段**。

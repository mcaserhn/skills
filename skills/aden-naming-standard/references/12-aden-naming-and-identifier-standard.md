## 1. 范围

### 1.1 本规范规定

1. **载体层**：新建文件与目录的命名式、扩展名前各段的取值与书写形式；
2. **数据对象**：数据平台内 schema / 库 / 表 / 视图的**对象名**构成、受控前缀与占位符取值域（§5.9）；
3. **编号分配**：项目组合、文档登记、ISMS 文件、业务域与子域等编号对象的**新号分配规则**；
4. **内容层**：文档、规格、看板**内部**标识码（接口码、开放点码、需求码等）的构成与书写；
5. **缩写与代号**：字母、缩写、枚举代号的引入与登记纪律；
6. **注册表**：上述取值所依赖的受控词表的权威位置、维护与审计方式。

### 1.2 本规范不规定

1. **存量对象的整改** —— 不发起重命名、不发起迁移、不发起合并（§1.3）；
2. **明文凭据治理** —— 文件内容中的凭据暴露属独立议题，与命名规范**分线处置**，本规范不承担该职责；
3. **非文档资产** —— 影像、字体、音视频等对象；
4. **业务系统内部主数据编号** —— D365 F&O / CE 的主数据编号由系统规则决定，本规范不覆盖。
5. **数据平台的物理落盘选型** —— 单库多 schema 与分库属**架构决策**（另有决策文档）；本规范只约束两种落盘方式下**对象名怎么写**（§5.9）。
6. **代码与脚手架的文件名** —— `app/`（原型源码）、`tools/`（脚本）、`config/`（注册表）、`.tmp/`（临时工作目录）下的文件，沿用各自技术生态的命名约定；本规范只约束其**目录归属**，不约束其**文件名**（故 §5.1 命名式对这些区域不适用）。
7. **项目本地文档目录的文件名** —— `docs/`（`NN-名称.md`，ISO 2145 应用）、`context/`、根级 `README.md` / `AGENTS.md` 等**项目本地文档**，沿用项目自身编号约定（附录 C 已判为符合），**不适用 §5.1 的 ADEN 载体层命名式**；其**正文内容仍受 §7、§8 约束**。

> **第 6、7 项的理由**：源码与脚本的文件名由语言生态决定（`package.json`、`index.html`、`ctx-lint.js`），项目文档则由项目自身编号体系决定 —— 强行套用 ADEN 文档命名式既表达不出、也无人遵守。**条款管得到、命名式写不出来**的规则等于无规则，故显式排除，而非留作解释空间。二者与 `output/`（**受管辖**，产物命名式见附录 C）的区别在于：`output/` 是交付物、需跨域分发；前两者是工程内部资产。

### 1.3 存量豁免（承重条款，执行者不得自行放宽）

> **本规范自生效日起只约束新产生的对象。**  
> 生效日之前已存在的文件、目录、编号与标识：**一律不重命名、不迁移、不重编号**。  
> 执行者**不应**以「不符合本规范」为由改动存量对象；如需整改，**应**另立专项决策。

**理由**：存量资产承载着跨系统引用、合同关系与审计留痕。批量重命名的断链风险，远大于命名混乱本身。

### 1.4 例外与系统产物

| 对象         | 形态                                           | 处置                                                                                                 |
| ---------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **系统异常产物** | 文件名尾部带 `-CCNLT<三字母>-<字母串>`                   | 成因：在线保存（OneDrive / SharePoint）失败时系统自动另存副本；绝大多数正常文件中不存在。**不应**人工模仿该后缀；**可**列为清理候选，但**须人工比对确认后方可删除** |
| **外部官方符号** | 微软官方名称（如 SKU 名 `Endpoint P2`、`Anonymous T1`） | **应**照抄原样，**不应**改造；**不应**与内部符号共用同一字母空间                                                             |

## 3. 术语和定义

| 术语         | 定义                                                              |
| ---------- | --------------------------------------------------------------- |
| **载体层**    | 文件、目录与对象（计算机名、账号、组、邮箱）的名称层。唯一性范围 = **路径内**                      |
| **内容层**    | 文档、规格、看板**内部**的标识码（如 `INT-01`）。唯一性范围 = **（类型 × 域）× 文档**         |
| **唯一性范围**  | 一个序号或标识"必须唯一"的边界；超出该边界允许重号                                      |
| **注册表**    | 受控取值的权威清单（如文档类型 5 类、技术域 9 域）。**一个注册表只有一处权威位置**                  |
| **受控值**    | 由注册表枚举、不得即席新增的取值（如状态后缀 5 值、语言段 2 值）                             |
| **注册项**    | 注册表中的一行；应含取值、语义、所属域、权威方、唯一性范围、生命周期状态                            |
| **存量对象**   | 本规范生效日之前已存在的文件、目录、编号或标识                                         |
| **数据对象**   | 数据平台内的 **schema / 库 / 表 / 视图** 等对象的名称层。唯一性范围 = **层容器内**（§5.9.8） |
| **系统异常产物** | 由在线保存失败等系统故障自动生成的对象（§1.4）                                       |

## 4. 命名总则

### 4.1 三轴

任何名称**宜**可分解到以下三轴：

```
轴 1｜是什么   —— 类型（文档类型 / 文件类型 / 记录 / 对象类型）
轴 2｜属于谁   —— 域（技术域 / 业务域 / 组织 / 站点）
轴 3｜第几版   —— 时间（版本号 / 日期 / 周期 / 状态）
```

新增命名式**应**能分解到三轴；不能分解的命名式**不应**引入。

### 4.2 两层的边界

| 层              | 对象                        | 实例                                                                                 | 唯一性范围                     | 取值来源   |
| -------------- | ------------------------- | ---------------------------------------------------------------------------------- | ------------------------- | ------ |
| **载体层**（§5、§6） | 文件 / 目录 / 身份对象 / **数据对象** | `AGI-Group Standard-Front End Naming Convention-v0.3.docx`；`dwd.stg_fo__vendtrans` | 路径内；**数据对象为层容器内**（§5.9.8） | §9 注册表 |
| **内容层**（§7）    | 文档内标识码                    | `INT-01`、`FR-09`                                                                   | （类型 × 域）× 文档              | §9 注册表 |

两层的轴逻辑相同，但**取值与唯一性范围各自独立**，**不应**互相套用。

**数据对象归载体层的理由**：`dwd.stg_fo__vendtrans` 与文件名一样，是"物理容器里放的东西叫什么"，其唯一性由容器（schema / 库）界定，其变更会引发引用断链 —— 与内容层标识码（文档内改动）性质不同。

### 4.3 通用字符纪律（全文适用）

1. **不应**使用国别字符（重音、波浪号等）；每个字符**应**能在任意键盘、任意语言环境下输入。
2. 复合名**宜**每部分仅首字母大写、其余小写。
3. **不应**使用空格与全角符号。
4. **段内分词靠大小写，段间分隔靠连字符** —— 二者分工，不互相替代（§5.2）。

## 5. 载体层命名规则

### 5.1 命名式

```
[组织前缀]-[文档类型]-[域]-[主体]-[版本][-状态][-语言][.扩展名]
   §5.3     附录A.1   附录A.2  自由   §5.4   §5.6   §5.7
```

| 段    | 是否必填 | 说明                  |
| ---- | ---- | ------------------- |
| 组织前缀 | 应填   | 受控（§5.3）            |
| 文档类型 | 宜填   | 取附录 A.1 五类          |
| 域    | 宜填   | 取附录 A.2 九域          |
| 主体   | 应填   | 自由文本，段内首字母大写        |
| 版本   | 宜填   | 受控（§5.4）            |
| 状态   | 宜填   | 受控（§5.6），置于版本**之后** |
| 语言   | 可选   | 受控（§5.7），仅双语并存时使用   |

> **适用范围（§5.1–§5.7 通用）**：本章只适用于**受管辖对象** —— `output/` 下的产物（附录 C）与 ADEN 组织文档名。**`docs/` `context/`（§1.2-7）与 `app/` `tools/` `config/` `.tmp/`（§1.2-6）不适用**：其文件名中的 `-prototype-`、`-design`、`-analysis` 等是**主体词**，**不构成** §5.6 的状态后缀；`README.md` / `AGENTS.md` 同理。

### 5.2 分隔符

- **段间**：连字符 `-`（唯一）
- **段内分词**：大小写（首字母大写），**不应**额外插入连字符
- **扩展名前**：点号 `.`
- **不应**使用：空格、全角符号、下划线 `_`、点号后带空格（`. `）、点号无空格式（`51.capex_`）

> 下划线 `_` 在存量中大量存在，**按 §1.3 豁免**；新产物**不应**引入。

**适用范围**：本节只约束**文件名与目录名**。身份对象（§5.8）与**数据对象（§5.9）另有分隔符约定**，本节的"禁用下划线"**不适用**于它们 —— 数据对象名中下划线是**必需**的（§5.9.5）。**代码与脚手架**（`app/` `tools/` `config/` `.tmp/`）按 §1.2-6 **不适用**本节；**项目本地文档目录**（`docs/` `context/`）按 §1.2-7 **不适用**本节。

### 5.3 组织前缀（受控）

| 前缀      | 适用      | 固定写法 |
| ------- | ------- | ---- |
| `AGI-`  | 基础设施类文档 | 全大写  |
| `ADEN-` | 合同与记录类  | 全大写  |

**不应**写 `Aden-`、`aden-`、`AdEn-`。

### 5.4 版本号（受控）

- **形式**：`-vX.Y` —— 连字符连接、**小写 v**、**至少两段**
- 第三段 `Z` **仅**用于不兼容修订（`vX.Y.Z`）
- **不应**出现：`-V1.0`、`V1.0`（无连字符）、`_v1.0`、空格分隔、单段 `V1`
- 文档内部历史表**可**使用纯数字（`0.1`、`0.2`），属表内约定，不受本条约束
- **版本号引用式**（正文中提及他处的版本时）：**可**写 `vX.Y`；**引用外部对象的 schema 版本**（如 `official-sources.json` 的 `schema v2`）**照抄原样、不改造** —— 它由该对象自身定义，不属本规范命名段（§7.2-8）

### 5.5 日期与周期（受控）

| 用途               | 形式                                                        | 例                                          |
| ---------------- | --------------------------------------------------------- | ------------------------------------------ |
| 文件名              | `YYYYMMDD`                                                | `20240522`                                 |
| 正文 / 表格字段        | `YYYY-MM-DD`                                              | `2024-05-22`                               |
| 期间区间             | `YYYYMMDD-YYYYMMDD`；沿用既有项目目录时**可**写 `YYYY.M.D ~ YYYY.M.D` | `20170110-20170410`                        |
| 月度 / 季度 / 半年 / 周 | `YYYYMM` / `YYYYQn` / `YYYYHn` / `YYYYWnn`（**周号补零**）      | `202603` / `2026Q1` / `2026H1` / `2026W10` |
| 期间标识段（可读式） | `YYYY-MM` | `2026-11` |

> **`YYYY-MM` 仅用于期间标识段**（period，如产物名与落盘路径中的报告期）。**日期语义（时点）不用它** —— 文件名用 `YYYYMMDD`、正文/字段用 `YYYY-MM-DD`。`YYYY-MM` 与 `YYYYMM`（紧凑式）互为变体，**同一产物族内应择一、不应混用**（对齐 §7.2-1「同族不并存两式」）。

**不应**使用 `mm/dd/yyyy`（仅存量文档历史表可见）。

### 5.6 状态后缀（受控 5 值）

```
-Draft  →  -Review  →  -Approved  →  -Signed  →  -Retired
```

- **位置**：**置于版本号之后**（`...-v1.2-Approved.docx`）；**不应**置于版本号之前
- 同一版本**不应**存在两种状态的文件并存；状态推进**应**覆盖，不另存为新文件
- **不应**使用散词：`Final` / `final` / `-s` / `-signed` / `Sample` / `_sample` / `previous` / `Archive` / `bkup` / `-old` / `_old` / `Copy` / `(1)(2)` / `-updated` / `UPD` / `-Ongoing` / `-Done` / `最终版` / `修改版` / `发布版` / `备份`

> **数据对象（§5.9）不适用状态后缀**：数据对象名**不应**带任何状态词或版本后缀（含 `_new` / `_final` / `_v2`），见 §5.9.7 第 5 条。
>
> **适用范围**：状态后缀**只出现在命名式的状态段**（`…-版本-状态-语言.ext`）。名称中作为**主体词**出现的同形词（`prototype` 设计文档、`archive` 目录）**不属**本条 —— 判定的依据是**段位置**，不是词本身。

### 5.7 语言段（受控 2 值）

`-zh` / `-en`（小写，置于状态段之后）。  
**不应**使用 `-cn` / `-中文` / `CN` / `EN` / `_EN` / `_ENG`。

### 5.8 对象命名（继承既有集团标准）

计算机名、员工账号、通讯组、M365 组、共享邮箱、共享邮箱（项目/系统/非用户）等对象的命名式，**应**遵循 `AGI-Group Standard-Front End Naming Convention v0.3`（**原文为准**）：

| 对象        | 命名式                                                        |
| --------- | ---------------------------------------------------------- |
| 计算机名      | `C<IATA 国家码 2 位><LT\|DT><Office 码 3 位>-<部门 3 位><名字前 3 字母>` |
| 员工账号      | `Firstname.Lastname<数字>@<域>`（`数字` 仅重名时用）                   |
| 通讯组 · 团队  | `<总部/区域>-<部门/职能>-<范围/子职能>`                                 |
| 通讯组 · 项目  | `<总部/区域>-<部门/职能>-<项目>`                                     |
| M365 组    | 同通讯组，**分隔符改为 `.`**                                         |
| 共享邮箱 · 职能 | `<区域/部门>.<职能>@<域>`                                         |
| 共享邮箱 · 项目 | `<区域+职能>.<项目>@<域>`                                         |
| 共享邮箱 · 系统 | `<名称>.noreply@<域>`                                         |

本规范**不重述、不改写**该标准；两者冲突时**以该标准原文为准**。

### 5.9 数据平台对象命名（内部条款来源，原文为准）

> **来源**：《ADEN 分层落盘构建块对照》**v1.4**（2026-09-28，Stanley HAO 编制）§3 / §4 / §5。  
> **本节的作用**：把该文档中**与命名有关**的条款归纳到本规范，使其与其他命名对象同处一处受控。  
> **效力**：**该文档原文为准**；本节与原文冲突时以原文为准。本节**不复制**原文的脚本代码与实现细节。  
> **落盘方式**：原文采用**单库多 schema**（原文 §4「方案 A」）；**分库**（原文 §5「方案 B」）为**备选、本期不实施**。  
> **共性**：两方案的**业务语义层命名完全相同**（§5.9.3–§5.9.6 通用），差异只在**物理容器段**（§5.9.2）与**跨库校验**（§5.9.8）。

#### 5.9.1 命名式

```
方案 A（采用）   <层容器> . <类型前缀>_<主体>
                 §5.9.2      §5.9.3    §5.9.4 · §5.9.6

方案 B（备选）   <库> . dbo . <类型前缀>_<主体>
                 §5.9.2          §5.9.3    §5.9.4 · §5.9.6
```

**段职责（方案 A）**

| 段        | 作用              | 取值                    |
| -------- | --------------- | --------------------- |
| `schema` | 定**层**与**权限边界** | §5.9.2                |
| 类型前缀     | 定**对象类型**       | §5.9.3                |
| 主体       | 定**业务含义**       | §5.9.4 结构 · §5.9.6 取值 |

**层信息应放在 schema（或库）而不写进对象名** ——

1. schema 是权限边界，换层即换权限；写进对象名则权限须另配；
2. 方案 B 下**应**保留 `dbo` 占位（库名已定层），**不应**在每个库内再建同名 schema —— 否则四段里三段说同一件事；
3. 方案 B 下对象名与库名**会**重复类型前缀（`stg_db.dbo.stg_fo__vendtrans`），此为**已知代价**：**冗余可读，缺失不可读**（跨库引用、血缘解析、日志排查都要回查库名）。

#### 5.9.2 层容器（受控）

| 方案        | 容器     | 取值                                                                                       |
| --------- | ------ | ---------------------------------------------------------------------------------------- |
| **A（采用）** | schema | `ods` · `dwd` · `dim` · `dws` · `ads` · `ads_<region>`                                   |
| **B（备选）** | 库      | `ods_db` · `stg_db` · `int_db` · `dws_db` · `ads_db` · `ads_<region>_db`；schema 恒为 `dbo` |

> 注意 A 与 B 的**层名不同映射**：A 只有 6 个 schema（`dwd` 兼承载 `stg_` 前缀对象、`dim` 承载 `int_` 前缀对象），B 把这两层各拆为独立库（`stg_db` / `int_db`）。名称**不应**跨方案混用。

#### 5.9.3 对象类型前缀（受控 6 值）

| 前缀     | 对象类型 | 语义                   | 所在容器（A / B）        |
| ------ | ---- | -------------------- | ------------------ |
| `stg_` | 表    | 单源清洗后的当前态，**不含业务逻辑** | `dwd` / `stg_db`   |
| `int_` | 表    | 跨源关联的中间结果            | `dim` / `int_db`   |
| `dim_` | 表    | 星型模型的维度表             | `dws` / `dws_db`   |
| `fct_` | 表    | 星型模型的事实表             | `dws` / `dws_db`   |
| `vw_`  | 视图   | 对外指标视图，**唯一出口**      | `ads*` / `ads*_db` |
| （无前缀）  | 表    | 贴源层，**保持源结构**        | `ods` / `ods_db`   |

**不应**即席新增前缀；新增**应**走 §9.3 登记流程。

#### 5.9.4 主体结构（按容器，即按层）

| 容器（A）          | 命名结构                            | 示例                                |
| -------------- | ------------------------------- | --------------------------------- |
| `ods`          | `<source>__<entity>`            | `ods.fo__vendtrans`               |
| `dwd`          | `stg_<source>__<entity>`        | `dwd.stg_fo__vendtrans`           |
| `dim`          | `int_<domain>__<verb_phrase>`   | `dim.int_pur__po_with_receipt`    |
| `dws`          | `dim_<entity>` 或 `fct_<entity>` | `dws.fct_purchase_order`          |
| `ads`          | `vw_<scope>_<domain>_<metric>`  | `ads.vw_cn_pur_po_ontime_rate`    |
| `ads_<region>` | 同 `ads`                         | `ads_id.vw_id_pur_po_ontime_rate` |

方案 B 下为同一结构前加 `<库>.dbo.`，例如 `stg_db.dbo.stg_fo__vendtrans`。

#### 5.9.5 双下划线切分（仅 staging 与 intermediate）

- staging 与 intermediate 层的对象名**应**用 **`__`（双下划线）** 分隔「源或域」与「实体 / 动词短语」；
- 实体或动词短语**内部**单词**应**用 **单下划线 `_`**；
- 解析器按 `__` **机械切分**（**不应**依赖语义推断）。

```
stg_fo__vendtrans          → 前缀=stg_   源=fo      实体=vendtrans
int_pur__po_with_receipt   → 前缀=int_   域=pur     动词短语=po_with_receipt
```


**不应**出现：缺 `__` 切分点、用单下划线代替切分点、在其余层使用 `__`。

> **与 §5.2 的关系**：§5.2「新产物不应引入下划线」约束的是**文件与目录名**；数据对象名按本条执行，两者**不冲突**。

#### 5.9.6 占位符取值域（受控）

| 占位符             | 取值                    | 扩展规则                   |
| --------------- | --------------------- | ---------------------- |
| `<source>`      | `fo` · `crm` · `fw`   | 新增源系统**应**先更新正则白名单     |
| `<domain>`      | `fin` · `pur` · `sal` | 新增业务域**应**经三方口径责任人确认边界 |
| `<scope>`       | `cn` · `id` · `grp`   | `grp` 待集团指定口径责任人后启用    |
| `<entity>`      | `[a-z0-9_]+`          | 小写字母、数字、下划线            |
| `<verb_phrase>` | `[a-z0-9_]+`          | 同上                     |
| `<metric>`      | `[a-z0-9_]+`          | 同上                     |

**宜**用 `<scope>` 而**不宜**用 `<country>` —— 三方口径裁决未必按国家划分（可能出现中印统一口径、按法人实体划分、集团合并口径）；写死国家维度会使规则与命名同时失效。

#### 5.9.7 禁止事项（数据对象，共 7 条）

| #     | 禁止项                                    | 拦截点                              |
| ----- | -------------------------------------- | -------------------------------- |
| 1     | 层前缀缺失                                  | Registry API 正则                  |
| 2     | ADS 视图不带 `<scope>` 标识                  | Registry API 正则                  |
| 3     | staging 模型跨表 join                      | SQL 解析：`FROM` / `JOIN` 数量 > 1 即拒 |
| 4     | 用人名、项目名、日期命名                           | 代码评审 + 正则黑名单                     |
| 5     | 使用 `_new` / `_final` / `_v2` 等**版本后缀** | 正则黑名单（对齐 §5.6）                   |
| 6     | 中文对象名                                  | `[a-z0-9_]+` 已隐含拒绝               |
| **7** | **与既有保留名冲突**（**绑定落盘方式**）               | 见下                               |

**第 7 条的分方案落地**

| 方案 | 子项 | 内容                                                  | 拦截点                          |
| -- | -- | --------------------------------------------------- | ---------------------------- |
| A  | 7  | 不得与既有 BI 分层、数据交换库**同名**（即使 schema 已隔离，迁移期人工操作仍可能误判） | P0 期把既有对象名导入**保留名清单**，注册时查重  |
| B  | 7a | 跨库同名对象                                              | 注册时查保留名清单                    |
| B  | 7b | 跨库引用超出方向白名单                                         | SQL 解析三段式引用后比对白名单            |
| B  | 7c | 视图中硬编码库名以外的连接串                                      | 禁止 `OPENQUERY` / 链接服务器引用同实例库 |

> **禁止项 4 与 §5.5 不冲突**：§5.5 允许**文件名**带日期段；数据对象名**不应**带日期。

#### 5.9.8 唯一性范围与校验

- 唯一性范围 = **层容器内**（方案 A：schema 内；方案 B：库内）。跨容器**可**重名。
- 校验**应**可机器执行（对齐 §10.1）：由 Registry API 的**正则 + 黑名单**落地，覆盖命名式、受控取值、补零与切分形式。
- **A 与 B 的校验强度不同**：方案 B **额外**需要**跨库引用方向白名单**（下游 → 上游允许，其余一律拒绝）—— 因为分库后每个库对其余库默认可见（同实例），不显式拦截会出现「`ads_db` 直接读 `ods_db`」这类跨层直达。方案 A 无此项：层间引用由 schema 权限天然约束。
- 正则原文与校验脚本见**该文档 §4.4（A）/ §5.4（B）**，本规范不复制代码。

#### 5.9.9 防撞词（`dim` 与 `dim_`）

| 词      | 身份                 | 出现位置                   |
| ------ | ------------------ | ---------------------- |
| `dim`  | **层**（schema / 库名） | 放跨源关联结果，对象名以 `int_` 开头 |
| `dim_` | **前缀**（对象类型）       | 维度表，出现在 `dws` 层        |

**应**由正则强制区分：`dim` 层只收 `int_*`，`dws` 层只收 `dim_*` 与 `fct_*`。方案 B 下该撞词**不存在**（`int_db` 与 `dws_db.dbo.dim_*` 不冲突）。

### 5.10 禁止事项（清单）

1. **不应**引入新的分隔符、新的状态词、新的语言词。
2. **不应**人工模仿系统异常产物后缀（§1.4）。
3. **不应**把内部枚举代号写进文件名（如 `W/A/P/L` 类代号，§8.3）。
4. **不应**在名称中使用国别字符、空格、全角符号。
5. **不应**同一对象并存多份仅状态词不同的文件（§5.6）。
6. **不应**在数据对象名中使用版本后缀、状态词或中文（§5.9.7）。

## 6. 编号规则

### 6.1 唯一性范围（Uniqueness Scope）

```
唯一性范围 =（对象 / 文档类型）×（域）
```

- 同一（类型, 域）内，序号**应**唯一；
- 跨（类型, 域）**可**重号，**不**视为冲突。

> **数据对象（§5.9）不适用本条**：数据对象**不编号**，其唯一性由**层容器**界定（方案 A = schema 内，方案 B = 库内），见 §5.9.8。

### 6.2 项目组合编号：五条线的定位（**不并轨**）

> **取值来源**：存量盘点与五线实测明细见 `docs/11` §2.4（**原文为准**）；本节只列**定位与分配规则**。

| 线  | 形态                           | 定位（语义）           | 已用范围         | 新产物去向         |
| -- | ---------------------------- | ---------------- | ------------ | ------------- |
| S1 | `N_名称`                       | 早期 capex/opex 项目 | 1–14         | 冻结（历史）        |
| S2 | `N. <capex\|opex>_名称 - 日期区间` | 项目组合（点号线）        | 1, 16–48     | 冻结（历史）        |
| S3 | 同 S2                         | 项目组合（点号线续）       | 51–60, 81–87 | **新项目组合项入此线** |
| S4 | `NNNN. 名称`                   | 知识域柜（四位，非流水）     | 1000–1004    | 按语义扩展         |
| S5 | `NNN_名称`                     | 文档登记（三位流水）       | 001–102      | **新文档登记入此线**  |

**「不并轨」的含义**：S1 / S2 / S3 物理上**不合并、不重编号**；跨线重号**继续共存**。新产物**应**在各线内**取本线空号**。

**成本标记**：新项目组合项**应**带 `capex_` 或 `opex_` 标记。**成本标记缺失**（S1/S2/S3 约 60 项中约 1/4 未标）属**存量**、按 §1.3 豁免，**不应**回溯补齐。

### 6.3 文档登记表

- 现存两份登记表**不合并**；**以 `2_ServiceSupport\08_Documentation` 为在用主表**（新登记入此），`backup\` 视为历史快照。
- 主表内序号**应**唯一、**只增不改**。
- 既有重号与缺失号**按 §1.3 豁免**，不回溯补齐。

### 6.4 ISMS 文件编号

```
<组织>-<域>-<子域>-<类型码><三位序号> <中文名>[ 版本]
```

- 类型码固定 4 值：`MAN` / `SOP` / `INS` / `FOR`；每类型**独立三位流水**
- 新增类型码**应**走 §9.3 流程；**不应**即席新增
- 记录表格类变体（无连字符、序号含范围）**按 §1.3 豁免**

### 6.5 业务域码与子域码

- 主域：两位十进制 `NN_名称`；子域同构
- `3` 为历史断层，**保留不占用**；**不应**为"补齐"而插号

### 6.6 并轨方案（仅备案，除另行决策不予执行）

```
若将来需并轨（须另立决策）：
  合并 S1/S2/S3 → 一线：NNN. <capex|opex>_<项目名> - <YYYY.M.D> ~ <YYYY.M.D>
  S4（四位）保留为知识域柜〔语义不同，不参与并轨〕
  S5（三位）保留为文档登记〔语义不同，不参与并轨〕
  历史重号 → 双方保留，加注「历史冲突」标记，不再新发
```

## 7. 内容层标识编码规则

### 7.1 标识式

```
<域前缀>-<类型码>-<序号>[<变体字母>]
```

| 组成           | 取值                        | 说明                                                                                     |
| ------------ | ------------------------- | -------------------------------------------------------------------------------------- |
| **域前缀**（可选）  | `INT-` / `EOD-` / `MD-` … | 标识所属域；**省略 = 文档级**（如 `OP-01`、`FR-01`）                                                   |
| **类型码**      | 2–4 字母，**应登记**            | `INT` 接口 / `OP` 开放点 / `A` 假设 / `FR` 需求 / `NFR` 非功能需求 / `BASE` 基线 / `MD` 主数据 / `EOD` 批次 |
| **序号**       | **≥2 位、补零**               | `INT-01`；超过 99 自然扩为 3 位，**不应**重编号                                       |
| **变体字母**（可选） | 小写 `a` / `b` / `c`        | 表派生或部分实现（`INT-01a`）                                                                    |

> **本条只管「内容层标识码」** —— 即标记文档**正文中对象**（需求、接口、开放点、假设…）的编号。**文档自身的结构编号**（章节号 `n.m`、附录号、条款号 `R-AB-n`、编号线 `S1`–`S5`、附录 B 事项号 `B-n`）**不属**本条，按 §3.1 的「自用编号体系」说明书写。

### 7.2 规则

1. **零填充统一 2 位**；同一文档内**不应**并存补零与不补零两式。
2. 类型码**应**登记于 §9 注册表；**不应**即席新造。
3. **域前缀决定唯一性范围**：`INT-OP01` 与 `OP-01` 属**不同命名空间**，**可**同号（对齐 §6.1）。
4. **范围引用**统一写 `起–止`（en dash）或「起 … 止」，**不应**混用两种写法。
5. **单字母类别码**（如 `S` / `C` / `N` / `B`）**应**先登记方可在正文使用；裸用视为缺陷（对齐 §8.1）。
6. **章节号**沿用 ISO 2145 多级十进制（`4.16.2`）；**章节范围**统一 `Ch<n>–<n>`（en dash），**不应**写作 `Ch0-13`。
7. **业务单据号**宜采用 `<业务前缀>+YYYYMMDD+<站点码>+<N 位序号>`；日期段一律 ISO 8601 基本式。
8. **规则陈述与引用不受前款约束**（**识别条款，防误报**）：
   - **反例**：为说明规则而举的**错误写法**（如第 6 条中的 `Ch0-13`）**不是**违规 —— 它是规则本身；
   - **证据引用**：**引用既有文档的实际编码**（如 Satellite FDD v1.8 的 `INT-1` ∥ `INT-OP1` ∥ `OP-1`、延迟类别 `S/C/N/B`）**不是**使用 —— 照抄原样，**不应**改造；
   - **外部编号**：`UTF-8` / `WCAG-2` / `ISO 704` / `GB/T 1.1` 等外部标准与技术编号，**不属**本规范管辖（§1.2-3）。
   判定时**应**区分「制造缺陷」与「记录缺陷」；后者**不应**计入不合规统计。

### 7.3 与载体层的边界

| 项     | 载体层               | 内容层          |
| ----- | ----------------- | ------------ |
| 对象    | 文件 / 目录 / 对象名     | 文档内标识码       |
| 唯一性范围 | 路径内               | （类型 × 域）× 文档 |
| 变更成本  | 高（引用断链）           | 低（文档内改动）     |
| 编号独立  | 二者**不应**互相引用同一序号池 | —            |

## 8. 缩写与代号纪律

### 8.1 六条规则

| #          | 规则                                                                               |
| ---------- | -------------------------------------------------------------------------------- |
| **R-AB-1** | **先定义，后使用**：任何字母或缩写首次出现，**应**在同句或同表给出全称；**不应**以「见上文 / 见前表」代替                     |
| **R-AB-2** | **必须登记**：唯一登记处见 §9；**未登记即使用 = 缺陷**，审计**应**报出                                     |
| **R-AB-3** | **一轴一套符号，字母不复用**：已被占用的字母**不应**再开新轴（占用情况**应**查登记表，不得凭记忆判断）                        |
| **R-AB-4** | **默认不缩写**：仅当同时满足「跨 ≥3 处引用」且「已登记」时，**可**引入字母                                      |
| **R-AB-5** | **枚举选项一律全称**：3–4 项的一次性枚举，字母**零信息增益**；确需编号时首引**应**带全称（如「推送（分发编号 D2）」）             |
| **R-AB-6** | **人机协作约束**：AI 生成内容中**不得**自造代号；确需压缩时**只能**复用已登记符号，或在正文内先给全称定义再使用。发现未登记代号**应**视为缺陷 |

> **R-AB-2 的过渡条款（至登记表建成）**
>
> ① **登记表建成前**（§9.2「缩写与代号（ADEN 级）」/ 附录 B-5），本规范及既有文档中**已有定义但尚未登记**的代号，**在首次出现处给出全称或明确定义即视为满足 R-AB-2**；登记表建成后**应**回填。
> ② 本规范**自用的编号体系**（章节号 `§n.m` / 附录号 `A.n`・`B-n` / 条款号 `R-AB-n` / 编号线 `S1`–`S5`）**不属** §7.1「内容层标识码」，不适用 §7.2-1 的补零要求（见 §3.1、§7.1）。
> ③ 本过渡**不豁免 AI 即席自造代号** —— 那由 R-AB-6 明令禁止；过渡只针对「**已有定义、尚未登记**」的既有代号。

### 8.2 同族陷阱（须警惕）

跨域同名符号（同一字母在不同域各有一套含义）**应**加**域限定前缀**（如「源-优先级」「待办-优先级」）—— 即 ISO/IEC 11179-5 的 **Scope** 原则。

### 8.3 反例（不得重演）

| 反例                   | 问题             | 正确写法                                                        |
| -------------------- | -------------- | ----------------------------------------------------------- |
| 托管四选 `W / A / P / L` | 单字母无定义处、跨会话无规律 | `WorkBuddy 云` / `租户内 Azure` / `Power Platform` / `本地原型`（全称） |
| 分发三式 `D1 / D2 / D3`  | 单点定义、跨文档裸用     | `拉取` / `推送` / `混合`（首次带编号）                                   |
| 单字母类别码正文裸用           | 定义只在某节，正文裸引    | 先登记，再使用                                                     |

### 8.4 排序（登记表内部）

登记表条目**应**按 **GB/T 1.1—2020 §3.2.8** 排序：大写拉丁 → 小写拉丁 → 无角标 → 字母角标 → 数字角标 → 希腊字母 → 特殊符号。

### 8.5 登记处分工

| 层级                    | 登记处         | 管什么           |
| --------------------- | ----------- | ------------- |
| **ADEN 级**            | 本规范 §9 注册表  | 域码、类型码、受控值、缩写 |
| **项目级**（如 StreamLens） | 该项目自有的符号登记表 | 该项目内部符号       |

**条款**（本文 §8）与**登记处**（各表）**不应**重复定义同一符号；有冲突时**以登记处为准**。

## 10. 合规与审计

### 10.1 合规判定

- 合规 = 符合**本规范**对应层的条款；
- 存量对象**按 §1.3 豁免**，**不应**计入不合规统计；
- 判定依据**应**可机器核验（分隔符、受控值、补零位数、状态词均在形式上可校验）。

### 10.2 审计方式

- 每季度**宜**以脚本**反向扫描新建资产**，输出不合规清单（**不扫描存量**，避免噪音掩盖真问题）；
- 清单**应**列出：路径、违反条款号、建议形式。

### 10.3 变更影响

- 注册项变更**应**记录「影响到的既有路径数」；
- 本规范修订**应**在下方修订记录留痕。

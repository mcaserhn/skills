# ADEN 命名与标识规范（装载版 v1.4）

**权威正文**：`references/12-aden-naming-and-identifier-standard.md`（v1.4，Stanley HAO 编制，
**2026-10-12 生效**）。本技能是它的**装载层** —— 把规范正文、底稿、上游依据与机器校验器
一次性带到手边，**不依赖任何外部项目目录**。

> **先读正文再动手。** 本文件只是索引与要点。遇到判断边界（某形态算不算违规）时，
> **以 `references/` 正文条款为准**，不要凭本文件的概括下结论。

> **路径基准（读命令前必看）。** 本文件里所有 `references/`、`scripts/` 下的路径都相对**本 skill 根目录**
> （这份 SKILL.md 所在目录），**不**相对你当前的工作目录。下文命令统一用 `$HD` 指代该根目录，
> 执行前必须展开成绝对路径。Windows 上把 `python3` 换成 `python`。

## 一、命名式（§5.1）

```
[组织前缀]-[文档类型]-[域]-[主体]-[版本][-状态][-语言][.扩展名]
```

| 段 | 必填 | 取值 |
|---|---|---|
| 组织前缀 | 应填 | §5.3 受控 2 值：`AGI-` / `ADEN-`（全大写，**不应**写 `Aden-`/`aden-`） |
| 文档类型 | 宜填 | 附录 A.1 五类：`Exploratory Study` / `Information Note` / `Position Note` / `Group Standard` / `Group Service` |
| 域 | 宜填 | 附录 A.2 九域：`00_FrontEnd` … `80_Patch` |
| 主体 | 应填 | 自由文本，段内首字母大写 |
| 版本 | 宜填 | `-vX.Y`（小写 v、连字符、≥2 段）；第三段仅用于不兼容修订 |
| 状态 | 宜填 | 受控 5 值，**置于版本之后** |
| 语言 | 可选 | `-zh` / `-en`，仅双语并存时用 |

## 二、最容易踩的四条（§4.3 / §5.2 / §5.5 / §5.6）

1. **禁下划线** —— 段间用连字符 `-`，段内分词靠大小写。下划线在存量中大量存在（**按 §1.3 豁免**），但**新产物不应引入**。
2. **禁空格与全角符号**（§4.3-3）。
3. **日期**：文件名段用 `YYYYMMDD`；**正文/表格字段**用 `YYYY-MM-DD`；**期间标识段**才可用 `YYYY-MM`；季度 `YYYYQn`（大写 Q）。
4. **状态后缀只有 5 值**：`-Draft` → `-Review` → `-Approved` → `-Signed` → `-Retired`。
   **不应**用 `Final`/`final`/`Sample`/`previous`/`Archive`/`old`/`Copy`/`updated`/`Done`/`最终版`/`备份` 等散词。

## 三、三条豁免（**先看这三条，否则会误报**）

| 条款 | 豁免什么 | 判据 |
|---|---|---|
| **§1.3 存量豁免（承重条款）** | 生效日（2026-10-12）**之前**已存在的文件/目录/编号 → **一律不重命名、不迁移** | 执行者**不得自行放宽**，如需整改须另立专项决策 |
| **§1.2-6 代码与脚手架** | `app/ tools/ config/ .tmp/` 下的文件 → **只约束目录归属，不约束文件名** | 理由：命名式"写不出来"的规则等于无规则 |
| **§1.2-7 项目本地文档** | `docs/ NN-名称.md`、`context/`、根级 `README.md` / `AGENTS.md` → **不适用 §5.1 命名式** | 正文内容仍受 §7、§8 约束 |

**两个判定纪律（实测踩过，别忘）**：

- **§5.6 判状态看段位置、不看词本身** —— `prototype` 设计文档、`archive` 目录里的同形词**不构成**状态后缀。
- **§7.2-8 三类不构成违规** —— 规则陈述里的**反例**、**引用既有文档的实际编码**、**外部编号**（`UTF-8`/`GPT-4`/`schema v2`）。

## 四、机器校验（§10.2 审计方式）

两个校验器，**规则同一套、作用域可切**。优先用 JS 版。

### 4.1 首选：`scripts/naming-lint.js`（权威实现）

Node 零依赖，含**全部**检查：载体层 6 条 + 内容层补零 + §8.1 待登记代号交叉核对 + 文件名未登记缩写。

```bash
HD=<本 skill 根目录的绝对路径>        # 即 SKILL.md 所在目录
node "$HD/scripts/naming-lint.js" --root <目标工作区> [--since 2026-10-12] [--all] [--csv out.csv]
```

### 4.2 备选：`scripts/aden_naming_lint.py`（无 Node 环境的子集）

覆盖载体层 6 条 + 内容层补零；**不含** §8.1 待登记核对与文件名缩写扫描。
`generic` profile 下与 JS 版的 ERROR 清单**逐条一致**（已在 StreamLens 上对拍：24 处命中、零差异），
不一致时以 JS 为准。

```bash
python "$HD/scripts/aden_naming_lint.py" --root <目标工作区> [--profile generic|lab]
                                         [--exempt-basis modified|created] [--all] [--csv out.csv]
```

| 参数 | 说明 |
|---|---|
| `--profile generic`（默认） | 按 §1.2-6/§1.2-7 字面列举：`app/ tools/ config/ .tmp/` 为工程区，`docs/ context/ README.md AGENTS.md` 为本地文档，其余受管辖 |
| `--profile lab` | 科研工作区适配：`lab/` 为工程区，受管辖 = `outputs/` 与 `other-archive/` 的交付物 |
| `--exempt-basis modified`（默认） | §1.3 按 **mtime** 判 —— 与 JS 版原口径一致 |
| `--exempt-basis created` | 按**创建时间**判（Windows `st_ctime`）。「先建后改」的文件在两口径下结论不同，属口径差异而非缺陷 |

两者退出码均为：0 = 无 ERROR；1 = 有 ERROR。清单输出**路径 / 违反条款号 / 建议形式**（§10.2 要求）。

### 4.3 用之前先定作用域

校验器**只扫新建资产**（§10.2 明示"不扫描存量，避免噪音掩盖真问题"），存量标 `[豁免]` 只备案。
若目标工作区的目录语义与上表不同（例如某工作区用 `research/` 承载源码），
**改 profile 的作用域列表，不改条款** —— 这是脚本头部注释里写死的纪律。

## 五、跑不通 / 判不了时怎么办

> 这一节是失败分支。上手顺序（§六）走不下去时先查这里，**不许自己发明做法**。

> **🛑 STOP**：校验器跑不起来 ≠ 可以改用手感判断。拿不到脚本结论时，只允许报「校验未完成」，**不得输出任何合规判定**。

### 5.1 校验器跑不通

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `node` 不存在，或 `node --version` 非零退出 | 切 `scripts/aden_naming_lint.py`（覆盖载体层 6 条 + 内容层补零） | 手工按 §5.1 命名式 + 附录 A 逐条比对，输出三列清单，结论首行标 `manual_audit` 声明未经脚本验证 |
| `Cannot find module …/naming-lint.js` | 把命令里的脚本路径改成本 skill 根目录的**绝对路径** | 同上 |
| 目标目录 `ENOENT` / `EACCES` | 确认 `--root` 为绝对路径、不含通配符 | 把原始错误原文交给用户，请其提供可读路径；**禁止**换个猜测路径重跑 |
| 脚本抛异常，退出码非 0/1 | 保留完整 stderr | 判为「校验未完成」，只报未完成；**禁止**凭印象给合规结论 |
| 两个校验器 ERROR 清单不一致 | 以 JS 版为准（§4.2） | 若 JS 版本身跑不起来，按本表第 1 行降级，清单标 `degraded` |

### 5.2 判定判不了

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 某形态在正文里找不到对应条款 | 依次查 §5（载体层）→ §7（内容层）→ 附录 A（受控值）→ 附录 C（既有判定） | 标 `待裁决` 并写明缺哪一条；**禁止**用「一般命名惯例」顶替 ADEN 条款 |
| 条款互相冲突（如受控值含空格 vs §4.3-3 禁空格） | 按 §1.3 存量豁免方向取宽，同时记录冲突条款号 | 升级给规范制定人裁决；**不得**在 skill 内自造新规则 |
| 校验器 ERROR 里混入作用域误报 | 先按 §1.2-6 / §1.2-7 过作用域，再逐条读上下文定性 | 逐条标 `false_positive` 附理由；**禁止**按命中行数机械判违规 |
| 判完不确定是不是存量 | 查 mtime / 创建时间，与 2026-10-12 比对 | 无法确认时按存量处理（§1.3 从宽），标 `exempt_unverified` |

### 5.3 三条不许

1. 校验器跑不起来时，**不许**凭对命名规范的印象直接下「合规 / 违规」结论。
2. 查不到条款时，**不许**拿通用命名惯例（小写、kebab-case 之类）顶替 ADEN 条款。
3. 作用域不确定时，**不许**默认全部受管辖——先按 §1.2-6 / §1.2-7 划界。

## 六、上手顺序

1. **读** `references/12-aden-naming-and-identifier-standard.md` 的 §1（范围与豁免）与 §5（载体层规则）—— 这两章决定 90% 的判定。
2. **查** 附录 A 的受控值汇总（可直接作为校验依据）。
3. **跑** `node "$HD/scripts/naming-lint.js"` 对目标工作区做一次反向扫描（`$HD` 见文首路径基准）。
4. 有 ERROR → 按 §10.2 清单给的"建议形式"整改。

   **🔴 CHECKPOINT —— 整改前必须停一次。** 改名 / 移动 / 迁移是**不可逆**动作，动手前做完两件事并拿到用户明确同意：
   - ① 确认该对象**不是存量**（§1.3：查 mtime 或创建时间，与 2026-10-12 比对）；
   - ② 向用户逐条列出「旧名 → 新名」对照，等其确认。

   未拿到确认前：**不得改名、不得移动、不得批量处理**。用户只要说"先看看"，就只交清单不动手。

5. 新建产物时**先套命名式**，别等审计时返工。
